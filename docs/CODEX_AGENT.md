# Codex Agent 集成

Novel Studio 把 Codex 作为独立 Agent 执行方式，而不是普通 OpenAI 模型配置。默认通道是随安装包发布并校验摘要的 `codex-acp` 1.6.2；ACP 在首个可观察输出前发生适配器、初始化、建会话或传输故障时，才进入只读 `codex exec` 兼容模式。首个输出后的故障保留原会话证据，等待作者主动重试。

每个 AgentRun 复用一个 ACP 会话。新章节、重新初始化项目或完全重新开始会创建新的 AgentRun。暂停会取消当前 turn 并保留会话；取消会关闭会话。

除创作助手的多步骤工作流外，故事字段、人物关系、世界元素、情节弧、章节规划、正文、选区重写、知识条目、连续性审计、质量评审、质量修复、提示词和文风都可以启动独立的轻量 AgentRun。项目保存默认执行方式，分裂按钮允许只覆盖本次调用；Codex 的运行轨迹、审批、候选和 Monaco 正文差异显示在当前页右侧侧栏，同时保留到创作助手历史。

Codex 只看到 `codex-workspaces/<agentRunId>`。镜像包含当前项目所需的故事基础、人物、世界、总纲、知识、连续性、当前章节和锁定能力包，不包含 SQLite、模型密钥、请求头、其他项目、应用日志或审批令牌。路径穿越、符号链接越界和 SQLite 路径会在进入审批前拒绝。

所有结果先进入候选区。作者确认后，Novel Studio repository 才在事务中写入正式项目；源摘要变化的候选会标记为 stale。尚未保存的关系、情节弧、知识、模板和文风表单使用 renderer draft，接受后只填入编辑器，仍需作者点击原表单保存。模型调用、镜像写入、命令、Web、MCP 与子 Agent 都按次审批，没有永久授权。

默认使用 ChatGPT 登录。存在 `CODEX_API_KEY` 或 `OPENAI_API_KEY` 时，设置页只显示“环境认证可用”，凭据不会写入 Novel Studio。设置页可查看适配器版本、CLI 版本、摘要状态、ACP 能力、会话状态和回退原因，并运行不写项目的连接测试。

2026-09-30 的模型更新加入 `gpt-6.1-sol`（GPT-6.1 Sol），内置 Codex CLI 固定为 0.159.2，ACP 适配器保持 1.6.2。设置页点击“刷新模型列表”，选择模型后会读取该模型的推理强度与 Fast mode 支持情况。已有运行继续使用启动时锁定的模型，新设置用于后续新运行。

## 模型目录与组件独立更新

打开模型设置时自动回读 ACP 模型目录，不使用固定模型白名单；新模型及推理强度、Fast mode 以运行时声明为准。成功目录缓存在当前应用数据目录的 `codex-model-catalog.json`，包含更新时间，不保存认证凭据或创作正文。目录缓存按运行时及登录文件身份隔离；更换账号或组件后重新读取。网络/诊断失败保留上次目录，但缓存不视作当前能力或账号权限证明。诊断仅建会话、读取配置并释放，不发送创作请求。

设置中的“检查组件更新”只查询官方 npm 目录；“更新 Codex 组件”独立下载 `@openai/codex` 的正式版本及对应平台包，固定 HTTPS 官方 registry、拒绝重定向、验证 SHA-512、拒绝归档越界和链接。下载与解包在后台线程进行，不修改书库，不需要系统 npm，也不执行 npm 安装脚本。组件位于应用数据目录 `codex-components/versions/<版本>/<平台>`，支持 macOS、Windows 和 Linux 的 x64/arm64。ACP 适配器仍为应用测试过的 1.6.2；适配器升级和协议调整走应用发布。

下载后校验本机摘要、exec 参数、ACP 协议及模型目录，再记录待启用版本。仍有运行、审批、诊断或未释放会话时不替换；空闲后自动启用，重启也启用已校验的待更新组件。不会自动更换默认模型。可“回退上一组件”或“使用内置组件”；损坏的独立组件不会遮挡内置兜底。只保留启用版和上一独立版，避免版本无限堆积。组件操作串行化，重复点击被拒绝，同版不重复安装。

这层独立更新不保证未来任何协议变化都自动兼容：新版 CLI 诊断失败时继续使用原组件并显示原因。也不会自动升级现有创作会话或重新运行创作。

2026-09-30 核验：`npm run check`、372 项单元/集成测试、源码及 macOS arm64 打包界面冒烟通过；测试书库路径在首次写入前验证位于独立临时目录。新增 17 项组件/缓存测试覆盖签名摘要、异常链接、Windows 平台路径、更新竞争、断线缓存、账号隔离、运行锁、延迟启用、重启和回退。真实官方 0.159.2 包在临时组件目录下载、验证摘要，并以 ACP 1 回读模型目录，未发送创作提示。Windows 包组装使用测试桩，尚未在 Windows 机器实装验证。此核验没有覆盖安装或修改真实书库。

## 书库位置和迁移（2026-09-30）

“模型与项目设置 → 书库与存储”显示当前目录、数据库大小、保留的原目录。
“更换数据目录…”选择已建立的空文件夹，保存迁移计划；可取消，或点击“保存退出并迁移”。
仍有创作、审稿、保存、删除或外接写入在执行时，重启迁移会被拦截。
退出走正常保存握手；保存失败保留编辑器，迁移不开始。

下次启动在后台线程执行迁移，进度窗口显示实际阶段和正在核对的数据表／文件。
使用 SQLite 一致性 `VACUUM INTO` 快照，包含 WAL 的已提交内容并回收数据库内部空闲页。
核对所有业务表的行数、逐行摘要、表结构、完整性和外键，以及全部附属文件的内容摘要。
确认一致后才原子更新位置配置；源数据库和原目录保留，未自动删除任何历史书稿或事件。
空间不足、内容变化、损坏、目录嵌套及符号链接问题会停止迁移并继续使用原位置。
复制中断后的文件也保留；另选空目录重试。已验证并发布、但丢失切换响应的迁移可重新核验后完成。

迁移范围：`novel-studio.sqlite`、`codex-projects/`、`codex-workspaces/`、`backups/`、`service-data/`。
系统应用目录仍保留 `library-location.json` 引导配置、Electron 缓存、`codex-components/`、
模型目录缓存、诊断以及 `creative-interface/` 固定入口和客户端凭据。
因此已有外接客户端仍读取原 `server.json`，重启后连接新端口；固定项目 ID 不变，
请求幂等回执、候选、来源校验和审批都随数据库保留。
新建书籍工作区／运行镜像使用新书库目录。已存在的 Codex 桌面对话不会自动移动其工作目录，
原工作区仍保留且可以继续通过受控接口操作同一项目；新任务使用新目录的项目描述符。

自定义磁盘暂时缺失时，启动会显示原路径并停止，不会创建空书库。
重新连接磁盘后再启动；必要时在应用关闭的状态核对 `library-location.json` 的
`directory` 与 `previousDirectory`，选择真实存在且已验证的原库恢复。
位置配置不要放进当前数据库，否则数据库失联时也会丢失查找入口。
推荐本机固定磁盘；此功能不是多电脑同时打开同一 SQLite 文件的共享方案。
跨电脑迁移还需重新登录 CLI、检查本机加密密钥与路径、重新准备专属任务。

### 按需读取与后台整理

UI 切书使用 `workspace:catalog`，返回目录和首章详情；切章使用项目校验的 `workspace:chapter`。
最近最多 8 章完整内容留在编辑器内存，其余只保留目录；快速切换的旧响应不覆盖最新选择。
全量 `workspace:snapshot` 与外接 `snapshot` 保持兼容，导出与上下文流程仍可读取完整数据。
schema v33 使用事务触发器维护章节字数，书架不再每次读取全部正文统计字数。
候选差异编辑器按需加载；定稿轮询不重叠，已完成记录停止轮询。

旧回执按持久化 rowid 游标每批扫描 100 行，压缩最多 10 条；新回执／晚完成请求用队列触发器捕获。
已处理的大回执不再重复全表扫描。已完成事件流的下一任务选择在写锁之外，
正式压缩批次内重新核对状态和游标，保留事件序号及审批等语义边界。
有前台写入、运行或外接排队时后台整理暂缓；连续整理的间隔由 2 秒放缓为 10 秒。
此轮没有按时间删除记录、改变创作上下文预算或将所有同步数据库调用改成异步。

验证：`npm run check`、`npm test`（380 项全部通过）、`npm run build` 与 macOS arm64 打包通过；
`scripts/smoke-library-storage.mjs` 使用实际路径校验的隔离书库验证 500 章导航、乱序响应、
保存后切章、章节卡保存、目录选择与取消、实际保存退出按钮、迁移重启、跨书正文与外接固定入口。
源码和 ASAR 安装包两条冒烟路径均通过；安装包迁移对 59 张表、1156 行模拟记录逐项核验。
这些是 Mock 工程测试，不发送真实模型创作请求；Windows 实机迁移仍需单独验收。

## 构建

`npm run build:codex` 从锁定依赖生成当前平台 `resources/codex-runtime/<platform>-<arch>`，记录适配器与原生 CLI 的 SHA-256。`npm run build:app` 会先构建 Creative Pack、Codex 运行时和 Go 服务，再生成桌面安装包。

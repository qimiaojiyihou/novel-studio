## 已实现的范围

`reader-service/fanqie-public-source.json` 是可通过阅读站现有 JSON 导入入口导入的书源，复用既有 Node.js 请求器、QuickJS 隔离规则、搜索票据、目录、入架和账号归属检查。没有新增 Java / Go 服务。初次隔离验证后，已按用户要求加入默认包并部署至正式站点：新版本 `global-all-sources-6a973045261560c6`，总数 45，原 44 条配置保持原样。部署、回滚和数据一致性记录见 `mobile-reading-1panel.md` 顶部。

仅读取 `fanqienovel.com` 的公开页面以及明确声明的 `novel.snssdk.com` 搜索入口。网页中的 `window.__INITIAL_STATE__` 通过有界对象扫描及 JSON.parse 读取，不执行网页脚本、IIFE 或尾随代码。付费/锁定标志、章节身份不匹配、空正文和未知字体字符均报错，不把乱码或预览缺失当作成功。

字符映射参考 `xjz6626/fanqie-tui/internal/fanqie/decode.go`，许可证见根目录 `THIRD_PARTY_NOTICES.md`。书源中的 `java.setContent/getString` 是现有 Legado 兼容 API 的命名，实际由 Node.js 实现，并不启动 JVM。

## 全本缓存调查结论

### 第十章之后提示错误的修正（本地已验证，尚未部署）

2026-10-16 对用户指定的《这个游戏不对劲，我挖矿成神！》／道不易进行只读抽样，精确书籍 ID 为 `7590221243043826712`。第 9、10 章返回完整内容；第 11、12 章的 `reader.chapterData` 返回 `isChapterLock=true`、`needPay=0`，content 长度约 200 字符。用户另提供已登录的原站截图，显示“扫码下载 APP 免费读，SVIP 网页畅读”。这只能确认当前网页访问边界，不等于 App 内收费，也不代表普通登录就能取得完整网页正文。

原规则主动拒绝锁定章节是预期行为；缺陷是沙箱把这个有意抛出的错误统一映射成“书源脚本执行失败或超过资源限制”。现已修正：

- 仅将固定的应用已知错误转换成受控错误码 `SOURCE_CHAPTER_LOCKED` 等；任意脚本异常文本继续脱敏，真正的执行/内存超限仍受原有预算限制。
- 阅读页显式进入锁定章节时显示紧凑提示，可复制该章节原站地址；不自动打开外站，不弹出 Cookie 收集表单。预取失败保持静默；当前章节和阅读位置保留。只输出严格匹配官方无查询参数章节 URL 的地址。
- 公开书源显示“高级配置／无需预先授权”；声明手动登录的书源显示“手动配置”；仅声明有效回传协议的书源显示“登录授权”。解析辅助 jsLib 不再被误判成登录需求。高级手动表单默认折叠，Cookie 可选且不承诺解锁。
- 没有修改默认书源版本、现有收藏或凭据，也没有实现全本缓存、客户端签名或受限正文获取。

验证：`npm run check:reader`、全量 `npm test`（489 通过，0 失败/跳过）；独立临时数据库浏览器冒烟 `scripts/smoke-reader-chapter-access.mjs`、`scripts/smoke-reader-network.mjs`、`scripts/smoke-reader-authorization.mjs` 通过。覆盖模拟第 10→11 章失败后保留位置、刷新恢复、空白/Escape 关闭、320px 布局、无外站自动弹窗、手动保存及真实回传协议的本地模拟。真实原站只做上述只读抽样；没有验证 SVIP 凭据或 App 访问权限。

### 后续缓存范围

检查过的 `zero199901/fqnovel-unidbg` 源码中，全本任务是读取目录后循环提交章节批次，并非获取一个整本文件 URL。其 `FQNovelService.batchFull` 使用 `/reading/reader/batch_full/v`，另有设备配置及签名服务依赖。这里的 `download` 模式参数不等于一个可匿名调用的公开整本下载接口，也未证明它就是当前官方 App 的全部缓存实现。没有调用该链路。

本次未验证到有文档支持、适合直接接入当前站点的官方整本缓存开放接口。目前阅读站网络书籍正文按章请求；浏览器的章缓存是内存 Map，主要用于翻页，尚不是整本持久化或断网阅读。

如后续开发缓存，应区分：

1. **服务端缓存**：Node.js 对可读取章节限速排队，支持进度、取消、断点、配额、版本失效和清理；账号/书源隔离，正文不放入事件日志。服务端缓存成功仍需要手机联网访问阅读站。
2. **手机离线缓存**：另行设计 Service Worker / IndexedDB 和账号退出清理、容量及版本策略，才适合断网阅读。

以上是待开发方案，不是本次已完成功能。

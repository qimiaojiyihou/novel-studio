# 书源兼容与故障处理（2026-10-16）

## v9：参考阅读 APK 的处理方式（已部署）

参考用户提供的阅读 APK（`io.legado.app.release`，3.21.011221）的静态证据改造；这是该版本的实现参考，不作为最新 Legado 的完整规范。没有运行 APK，也没有登录真实书源。

- **身份与请求域分离**：完整 `bookSourceUrl` 的路径、查询和片段可区分同站变体；发请求时移除片段。普通根域书源保留旧 ID。旧账号中既有的域名别名、收藏和加密授权保留，不把旧别名的 Cookie 复制到新变体。允许访问的域名仍单独校验。
- **变量作用域**：搜索列表每行独立；选书后进入书籍作用域，读章进入章节作用域。读取依次回退到书籍和请求变量。`bookName`、`title` 分别提供当前书名、章节名。支持 `@put:{"id":"$.id"}`、`@get:{id}` 和脚本 `java.put/get`；列表 `%%` 按位置交错，较长列表的尾部不丢失。文本选择器也支持交错合并。
- **持久化与并发**：新增 `network_book_state`，按账号、书籍和源规则版本 AES-GCM 加密。搜索票据仅在服务内存携带变量，公开结果不包含变量。成功加入或读取后提交；并发不同章节合并，同键冲突拒绝覆盖。删除收藏级联清理；源版本变化时要求重新搜索并加入以重建变量，保留原书籍 ID 和阅读进度。无变量变化不反复写数据库。
- **动态请求头**：`header` 支持 JSON 或 `@js:` / `<js>` 脚本，在既有 QuickJS 隔离环境生成。公共请求头继续走白名单；Cookie、Authorization 和 X-Api-Key 作为内部凭据，只发给书源精确来源，允许跳转到另一个域名不等于允许转发凭据。补充有界的 `java.md5Encode` 和不输出凭据的 `java.log`。脚本依旧有 CPU、内存、调用次数和请求上限。
- **登录反馈**：明确的上游 401、登录页，以及显式要求登录的源返回 403 时，返回 `SOURCE_LOGIN_REQUIRED`（422）及公开源 ID，不把读者退出阅读站。旧请求晚返回，不标记新配置过期。普通 403 / 人机验证继续单独诊断，未据此删除书源。
- **手机操作**：搜索异常可点“登录此书源”，加入书架失败显示同样入口；前台读章失败打开对应源登录配置。预取失败不弹窗、不自动开标签。状态区分未保存、已保存未验证、验证通过、过期。

### 登录能力边界

APK 的原站 Cookie 自动回收依赖 Android WebView / CookieManager，H5 页面没有同样的跨域 Cookie 读取能力。本轮复用已实现的 `fragment-v1` 显式授权回传；支持回传的服务可自动保存，其余书源保存本人的 Cookie / 参数一次后复用，过期再更新。未实现通用浏览器渲染、资源嗅探、任意原站 token / localStorage 自动抓取，不把 `webView:true` 当成普通 HTTP 请求运行。

不照搬样本里忽略证书的网络设置；TLS 验证、公网 DNS 固定、跨域允许列表和 HTTPS 降级拦截继续生效。源站 404、429、人机验证或站点下线不靠改规则宣称恢复。

## 本次修复

- 支持 XPath 末尾 `@html` / `/html()` 提取正文，保留段落与换行，排除活动标签。识别旧导出器无实际内容的登录地址描述，真实登录脚本继续校验。
- 扩展有界的静态版本号/应用标识请求头；传输层继续管理 Host、Cookie 和连接。双栈连接可在已逐项验证的公网 DNS 地址中选择，证书验证、跳转复核、请求数量与超时限制保持生效。
- 搜索异常和默认包诊断按跳转、证书、访问受限、地址、连接、规则等分类折叠，保留逐源原因与字段。不将所有错误挤成一个连续段落。

## 跳转域名的处理

1. 在管理书源中勾选该源，执行检测。
2. 当前版本检测为 `ORIGIN_BLOCKED` 时，显示目标来源和“确认跳转域名”。
3. 用户先核实域名仍属原站；确认后只为当前账号的此书源添加该精确来源。
4. 再次搜索或检测。证书验证、公网 DNS 验证、HTTPS 降级拦截仍执行，不意味着验证通过。

接口为 `PUT /api/network/sources/:id/origins`，输入 `{origin}`。只接受本账号此源当前规则版本、24 小时内最近检测记录中的目标；规则变化、账号不符、目标不符或过期均拒绝。此更新成为用户自定义版本，默认包升级不会覆盖。

## 默认包与数据保护

v8 的合并包为 245 个书源身份：184 个通过规则校验，61 个保留待配置/兼容登记。v9 按完整标识重新生成，296 条原始记录合并 36 条重复，保留 260 个独立条目：196 个通过规则校验，64 个待配置/兼容。数量口径因身份拆分变化，不能用两版待兼容条目数直接推断兼容退步。**规则校验不等于源站在线，更不等于全书正文可读。**

v9 包版本 `global-all-sources-3fe401f060977a52`（此前 v8 为 `global-all-sources-80ec4d4a572ae7cb`）。更新已有受管配置和旧诊断，但保留用户自定义版本、启停选择、删除记录、账号凭据和收藏。升级链累加新增身份，不恢复已删除的旧身份；新增完整标识变体不复制旧域名别名的授权。既有账号可能另有历史别名或自定义源，显示总数可超过 260。3 个此前重复 DNS 失败的地址及其变体仍保留待核查登记，不盲目复活。

默认包不携带原文件的共享 Cookie、硬编码登录凭据或待执行的原始不兼容规则。

## 仍需分别处理的情况

- HTTP 403 / 登录页 / 人机验证：遵循原站要求，使用本人登录配置；不进行重试风暴或自动弹标签页。
- 429 / 503：尊重 Retry-After 与同域冷却；稍后重测。
- HTTP 404 / 410：需要维护者提供当前有效的入口或新版规则，不能仅修改解析器宣布恢复。
- TLS / 证书失败、外站连接超时：保持区分诊断，等待站点修复或排查部署服务器网络；不忽略证书、不降级到 HTTP。
- 64 个登记中仍包括 WebView 渲染、特定脚本/加解密接口、无效地址、内置私人凭据及未配置的 FQWeb 服务模板。`@put/@get` 本身已支持；其他缺口继续逐项诊断，没有被伪装为可运行书源。

# Novel Studio 创作对话复用

构建标识：`creative-upgrade-2026.09.08-context-reuse.1`

## 目标

在保持项目、章节、候选和审批隔离的前提下，减少重复发送长篇上下文：

- 同一本书的设定与规划任务使用书级规划对话。
- 同一章节的章节卡、场景计划、正文和局部修改使用章节级创作对话。
- 不同章节自动使用不同对话。
- 独立审稿、连续性检查、章节状态提取和设定影响分析不继承创作讨论。
- 新创作目标复用旧对话前会检查步骤数；已有 8 个步骤时自动建立新对话。候选内部的连续修改仍保留在当前候选对话中。

## 上下文发送规则

首轮始终发送完整、可追溯的正式上下文。同一 AgentRun 的 ACP 会话仍在当前应用进程内存中时，后续轮次比较上一轮 `contextSources`，只发送新增或摘要已变化的上下文条目；未变化条目由同一会话历史继承。

以下情况始终回退到完整上下文：

- 应用重启后恢复持久化会话；
- ACP 会话已经释放或需要重新创建；
- 上一轮没有可核对的上下文来源快照；
- 对话范围发生变化；
- ACP 在输出前失败并转为 exec 兼容模式。

生成记录同时保存完整上下文快照、是否具备增量复用条件、完整与增量消息字符数、实际执行采用的 `full` / `delta` 模式及模型 usage，便于排查和比较。

## 并发与未决候选

只有在旧对话没有运行中步骤、没有待确认候选、模型路由兼容且未超过步骤上限时，新的同范围任务才会复用旧 AgentRun。存在未决候选时，新目标会建立独立运行，避免把两个尚未确认的结果混入同一对话。

## 验证

覆盖范围：

- 规划任务跨字段复用；
- 同章跨章节卡、场景和正文复用；
- 跨章隔离；
- 审稿与检查隔离；
- 8 步后轮换；
- ACP 仅在内存活跃会话采用增量消息；
- exec 回退和会话恢复使用完整消息；
- 增量只包含新增或摘要变化的正式来源。

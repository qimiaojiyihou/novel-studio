# 定稿后文字校正

构建：`creative-upgrade-2026.09.07-proofread.1`。沿用 schema v24、备份 v8，无书库迁移。

## 作者操作

1. 已经完成过定稿的章节旁新增“定稿后校正”。修改正文仍自动保存，但界面显示“修订待审”，不再与首次草稿混为一谈。
2. 入口先展示与最近定稿的完整变更范围；此前有校正时同时展示与原模型审稿正文的累计差异。原文和当前保存稿可展开对照。大范围重写可能显示一个完整范围，不隐藏正文，不把字符数量当作语义判断。
3. 仅错字、标点、排版校正：核对差异，填写校正说明，勾选未改变剧情、人物事实和交接含义，再确认恢复定稿。不调用模型。
4. 若原交接引句受影响，逐项粘贴当前保存稿中的原句并本地验证。事实内容保持原样；这里不支持移除条目或改写交接事实。事实本身有变化时走原完整定稿流程。
5. 成功显示“已定稿·已校正”，明确标注“沿用原审稿，经作者校正”。原审稿不冒充新模型评审。没有真正完成过定稿的章节仍需完整流程。

不会自动恢复真实书库中的历史草稿，也不按差异比例放行。哪怕只改一个“不”，也必须由作者核对含义。仅保存相同正文或另存版本不再把定稿降为草稿。

## 工程边界

- `chapter-amendment.js` 只读取已保存正文。来源项目、章节、最近定稿、状态摘要和预览指纹均由主进程核对；校正请求不接受新正文。
- 作者确认、校正说明和稳定请求 ID 为必填。事务内创建新 revision、新 finalization，然后复用现有正式交接确认事务。旧 revision、模型原审稿、原候选和历史交接记录均保留。
- 新记录 `checks.authorAmendment` 保存累计与本次差异、作者声明、引句修正、原审稿/前次定稿 ID 和请求指纹。新记录不创建 AgentRun，不复用旧运行 ID 冒充新审稿。
- 当前记忆和已确认知识来源一起更新；任一正式写入失败整体回滚。重复请求恢复同一回执；相同请求 ID 的不同参数拒绝执行。
- 文本、交接或其他依赖在预览后改变时拒绝写入。已有未结束定稿/创作目标先由作者处理，不自动取消。正文以外的过期依赖仍要求重新审稿。
- 旧历史定稿的过期检查只影响它对应的来源 revision，不再污染较新的正式记忆；较新校正版本自身的来源依赖仍正常失效。其他章节不会被批量恢复。
- 校正历史沿用既有项目备份 JSON 链接重映射；上下文只携带简短来源说明，不带整份校正差异与作者审计文本。

## 专属创作接口

`finalization.correction-preview` 为只读，参数 `chapterId`。`finalization.correct` 为正式决定，参数是预览中的 `chapterId/baseFinalizationId/sourceDigest/stateDigest/previewDigest`，加 `confirm:true`、`meaningUnchanged:true`、实际 `reason`，以及可选 `corrections:[{key,index,quote}]`。外层仍须稳定 requestId。

两者沿用项目绑定校验，校正提交与前台共享项目队列。切换前台不改变绑定，跨书访问拒绝。operator Skill 的允许清单和说明同步；书籍目录中的已安装副本需通过现有受保护安装器更新，不覆盖作者自定义文件。

- `npm run check`、`npm test`、`npm run build`。
- 新 `tests/chapter-amendment.test.js`：差异重放、错字、否定词声明、累计修改、受影响引句、并发、幂等/丢失响应、重开数据库、项目隔离、来源过期、事务回滚和备份往返。
- operator 测试补充作者语义声明门禁；既有单书/双书、定稿、审批和浅色界面测试保留。
- `scripts/smoke-creative-upgrade.mjs --development --handoff-repair --proofreading`：实际编辑器自动保存、表单反馈、受影响证据修改、状态恢复、保存版本不降级、刷新持久化与累计差异。只运行本机 Mock：原审稿和交接各一次，校正新增调用数为零。
- 打包版用相同脚本省略 `--development`，并通过 `NOVEL_STUDIO_TEST_APP` 指定测试应用。
- 所有测试书库写入前核对 SQLite 或主进程返回的实际路径。真实书稿的语义判断与真实模型效果不属于 Mock 验收结果。

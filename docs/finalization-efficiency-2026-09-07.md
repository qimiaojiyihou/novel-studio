# 定稿耗时优化 · 2026-09-07

构建标识：`creative-upgrade-2026.09.07-finalize.1`。

## 使用变化

1. “完成本章”面板先做本地检查，不启动模型。作者集中完成正文修改，再点“集中修改已完成，开始独立审稿”。
2. 同一正文摘要、同一审稿配置重复点击仍聚焦已有任务。修改正文后旧报告保留参考，新稿重新检查；没有把旧报告自动当成新稿的模型审稿结论。
3. 新定稿使用 `delta-v1` 交接：只提取当前正文里的关键变化、知情变化、伏笔和承接点，不复制整份人物/道具库存。条目数量是精简建议，不强制裁剪有效事实。
4. 交接引句校验失败时保留整个结果。面板按类别和条目定位，支持替换证据原句，或明确移除没有本章依据的条目。填写核对原因后本地重验，不再生成一份交接。
5. 完成确认前不写入正式知识。作者修正与模型原候选分别留档；摘要、正文来源、修正原因及差异可追踪。

GPT-6 Astra、极高推理及当前模型授权策略保持不变。工具审批、独立审稿和最终交接确认继续有效。

## 工程边界

- `chapterStateMode` 在定稿记录的 `checks_json` 和新交接运行的 `model_routes_json` 中冻结；不修改已发布 Creative Pack 的版本内容，旧运行没有该标记时仍使用旧模板。
- 精简交接由受保护的主程序定稿编排提供，使用原任务 Schema；PromptSnapshot@7 记录实际编排、编译器版本、消息和当前正文依赖。
- 交接提取不再加载规划、全书旧状态和文风提示词。后续正文创作仍使用正式设定、上一章交接和按相关性召回的旧章记录；旧章信息带来源章节，不伪装成当前全量状态。
- 修正只支持修改既有条目的 evidence 或移除该条目；主进程重新校验正文摘要与交接摘要、条目归属和每段引句。未选中的内容原样保留，状态已过期/取消/定稿时拒绝覆盖。
- 修正审计单独保留，检索时不把被移除的错误条目和审计全文重新送回模型。
- 校验失败本身不再触发隐藏重生成。历史失败任务若还有待确认候选，恢复时先取回已有候选；没有结果的网络/执行失败仍保留现有显式恢复与最多三次限制。
- 沿用 schema v24 与备份 v8，新增数据放在既有 JSON 字段中；小说正文和已确认历史数据无需迁移。

## 验证

`tests/finalization-efficiency.test.js` 覆盖零调用本地检查、单次审稿、精简/旧模板隔离、保留无效交接、重启恢复、引句修正、版本冲突、取消、模型原始候选保留、正式知识事务、备份往返、历史来源召回与审计隔离。

桌面工程测试：

```sh
node scripts/smoke-creative-upgrade.mjs --development --handoff-repair
npm run build
node scripts/smoke-creative-upgrade.mjs --handoff-repair
```

Playwright 不在项目依赖里时用 `NOVEL_STUDIO_PLAYWRIGHT` 指向已安装的 Playwright ESM 入口。测试创建临时数据库，只请求本机模拟服务。`--handoff-repair` 故意返回一处错误引句，验证修正后完成定稿且总计只有两次模拟调用（审稿一次、交接一次）。模拟文本是工程夹具，不用于评价创作效果。

打包验证可用 `NOVEL_STUDIO_TEST_APP` 指定已构建可执行文件。开发版与打包版均必须尊重显式的 `NOVEL_STUDIO_TEST_USER_DATA`；测试在第一次写入之前核对主进程返回的真实数据库路径，缺失、错误或符号链接指向其他数据库时立即停止。`tests/smoke-isolation.test.js` 覆盖这道前置隔离检查。旧打包版忽略测试数据目录的行为已修正。

这些验证证明重复调用和恢复路径得到改善，不代表真实 GPT-6 用时或文学质量已经完成对比验收。
